# 03 - Automatic `sort_key` Update Triggers in Product Handlers

## Описание
Встроить автоматический пересчет и сохранение поля `sort_key` во все обработчики, где создаются или изменяются товары и их характеристики, а также при изменении порядка свойств в админке.

## Требования

1. **Редактирование товаров в админке (`server/api/admin/cms/products/updProds.js`):**
   - Выполнить штатный SQL `UPDATE` для пришедших полей.
   - Если среди обновленных полей присутствуют `category_id` или характеристики `p0_brand` ... `p8_pack`, собрать ID измененных товаров.
   - Вызвать `await recalculateProductsSortKey(updatedIds)`. Метод пересчета загрузит полные актуальные строки из базы и запишет корректный `sort_key` (исключает потерю неуказанных в запросе характеристик).

2. **Импорт товаров (`server/api/admin/dbImport/products.js`):**
   - При создании/перезаписи товаров вычислять `sort_key` перед пакетной вставкой в `i_products`.

3. **Изменение порядка свойств в админке (`server/api/admin/setProperties.js`):**
   - Если администратор изменил значение поля `ordering` для свойств в таблице `i_properties`:
   - Собрать массив всех измененных `prop.id` по итогам всей входящей пачки.
   - Найти все товары, у которых в полях `p0`...`p8` используется любой из этих `prop_id`:
     `SELECT id FROM i_products WHERE p0_brand IN (?) OR p1_type IN (?) ...`
   - Вызвать `await recalculateProductsSortKey(affectedIds)` один раз в конце запроса.

## Критерии приемки
- [x] При изменении любой характеристики товара через админку его `sort_key` сразу обновляется в БД.
- [x] При частичном обновлении товара (например, только `p2_counting_system`) остальные характеристики в ключе не теряются.
- [x] При импорте товаров поле `sort_key` заполняется автоматически.
- [x] При изменении `ordering` свойства в справочнике `i_properties` зависимые товары пакетно обновляют свои ключи.
- [x] Отсутствует рассинхронизация между характеристиками товара и его `sort_key`.
